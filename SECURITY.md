# Безопасность Tamyr

Кратко: что защищено, чем это проверено и что владелец проекта должен включить сам в настройках Supabase.

## Модель угроз

Сайт — статические файлы на GitHub Pages. Всё, что лежит в браузере (код, `js/config.js`, публичный ключ Supabase), видит любой посетитель, поэтому **защита — только на сервере**: правила доступа к строкам (Row Level Security) в базе и проверки в функциях Supabase. Интерфейс лишь прячет лишнее; полагаться на него нельзя.

Пользователи — в основном несовершеннолетние, поэтому данных минимум: имя, почта и прогресс. В журнале ответов и в запросах к ИИ имени и почты нет.

## Что защищено и где

| Что | Правило | Где |
|---|---|---|
| Прогресс ученика | читать и менять — только сам ученик; учитель его класса — только читать и только пока у него роль `teacher` | `schema.sql`, `classes.sql` |
| Роль учителя | ставит только владелец проекта (`set_teacher` закрыт для всех ролей сайта); хранится в `app_metadata`, которую пользователь изменить не может; проверяется по базе, поэтому снятая роль действует сразу | `teachers.sql`, `classes.sql` |
| Классы | создать — только учитель (`create_class`), вступить — только по коду (`join_class`), напрямую в таблицы писать нельзя; ученик видит только свои классы | `classes.sql` |
| Журнал ответов | писать и читать — только свои строки; гость — ничего; выгрузка для анализа — без id аккаунта | `answers.sql` |
| Пробный ЕНТ | видит, вносит и удаляет только учитель класса, пока у него роль `teacher`; писать — только через `save_mock_test` (ученики не из класса отбрасываются); ученикам и гостям недоступно; выгрузка — без id аккаунта | `mock.sql` |
| ИИ-объяснения | ключ Anthropic только в секретах Supabase; функция проверяет вход ученика сама; 20 объяснений в день на ученика; входные данные обрезаются; имени и почты в запросе нет | `functions/explain`, `ai.sql` |
| Отображение | всё, что пишут пользователи (имена, названия классов), выводится через экранирование; в CSV для Excel ячейки, начинающиеся с `= + - @`, экранируются (защита от «формул» в именах) | `js/app.js`, `js/teacher.js` |

Подбор кода класса не даёт доступа к чужим данным: вступивший открывает учителю **свой** прогресс, а не получает чужой.

## Чем проверено

- `sh tools/test_sql.sh` — все `supabase/*.sql` на настоящем PostgreSQL 16 (дважды, повторный запуск безопасен) и 18 сценариев доступа: ученик пытается стать учителем, учитель читает и пытается изменить прогресс, другой учитель, снятая роль, выход из класса, гость, лимит ИИ, журнал ответов, пробный ЕНТ. Результат сравнивается с эталоном `supabase/test/rls.expected`.
- GitHub Actions (`.github/workflows/tests.yml`) запускает это и тесты в браузере на каждый push и pull request.
- Ограничение: `supabase/test/shim.sql` имитирует роли и `auth.uid()` Supabase. Сами правила выполняются по-настоящему, но проект в облаке стоит один раз проверить руками: вторым аккаунтом не видно чужого прогресса.

## Что включить в Supabase вручную

- **Authentication → Providers → Email:** «Confirm email» — включено.
- **Authentication → Policies / Passwords:** минимальная длина пароля 8 (как в приложении); защита от утёкших паролей (Leaked password protection), если доступна на тарифе.
- **Authentication → Rate Limits:** оставить ограничения на письма и входы.
- **Edge Functions → explain:** «Verify JWT» выключено (функция проверяет вход сама); ключ — только в Secrets.
- **Anthropic Console:** месячный лимит расходов.
- **Table Editor:** у таблиц `progress`, `answers`, `classes`, `class_members`, `ai_usage`, `mock_tests`, `mock_results` должна стоять отметка RLS enabled.

## Известные ограничения

- Данные хранятся у Supabase за пределами Казахстана. Для пилота с согласием родителей это допустимо; до масштабирования на школу нужно решить вопрос хранения в РК.
- Количество записей в журнал ответов не ограничено: ученик может засорить свои строки. Вреда другим нет; если станет проблемой — ограничение по частоте на стороне базы.
- Согласие родителей — отметка ученика при регистрации, а не проверенное согласие. Для пилота нужны бумажные согласия.
- Результаты пробного ЕНТ остаются у учителя, даже если ученик вышел из класса (учитель и так знает их по бумажной работе). Удаляются вместе с аккаунтом ученика, с классом или кнопкой «Удалить» у работы.
